# 程式開發行為準則與技能 (Karpathy-Inspired Skills)

本技能旨在減少大型語言模型在編碼時的常見錯誤，包含以下核心原則：

## 1. 編碼前思考 (Think Before Coding)
*   **不隨意假設**：遇到模糊不清的需求時，需提出澄清。
*   **不隱藏困惑**：面臨多重設計路線或不確定時，向使用者說明並確認。
*   **展現權衡方案**：說明不同做法的優缺點。

## 2. 簡潔優先 (Simplicity First)
*   **極簡實作**：使用最少量的程式碼達成功能。
*   **不預做過度設計**：不要自行預測需求添加未要求的靈活性、可配置性或多餘抽象層。
*   **拒絕死程式碼**：確保沒有無用的冗餘程式碼殘留。

## 3. 精準修改 (Surgical Changes)
*   **最小化修改範圍**：只改動受影響的部分，不擅自更改其他無關檔案的排版、排版格式或註釋。
*   **遵循既有風格**：嚴格匹配專案現有的程式碼命名與架構風格。

## 4. 目標驅動執行 (Goal-Driven Execution)
*   **驗證成功標準**：在開始前確定如何驗證修改（例如：單元測試、編譯執行或 API 回傳值驗證），並循環測試直至完全符合預期。

## 5. 文化風格與用語規範 (Cultural & Terminology Guidelines)
*   **排除中國風與中華元素**：在進行遊戲化設計、奇獸、角色、文案、介面風格或稱號設計時，**嚴格排除任何「中國元素/中華元素」**（嚴禁使用九天、神龍、靈氣、修煉/修練、仙俠、修真、大宗師、武俠、江湖等中國古代神話/仙俠術語）。
*   **全面採用國際普世奇幻冒險風格 (Universal Fantasy RPG)**：奇獸角色與遊戲回饋採用健康、現代、國際通用的奇幻冒險風格（例如：奇獸蛋 ➔ 烈焰赤狐 ➔ 疾風獵豹 ➔ 星穹巨龍 / 獅鷲 / 飛馬等）；遊戲動態與系統文案採用現代教育或國際電競常見詞彙（如：鍛鍊、挑戰、能量、升級、大師）。
*   **嚴格在地化台灣語法與口音**：各項數學發音、教學用語均恪遵台灣教育部國小數學課綱語法（例如：「A 乘以 B」、「多少 乘以 B 等於 C」），語音合成強制指定台灣繁體國語（`zh-TW`）與漢字轉音。
